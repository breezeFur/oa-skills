# Agent 执行韧性（空壳清理 · 失败不卡死）（强制）

> **适用**：API/脚本搭建或改报表全程。  
> **目标**：失败不留垃圾空壳；单点报错不拖死整单，先交可用结果、再提示用户、最后可后台补救。

---

## 一、失败 / 终止必须清理空壳报表（强制）

### 1.1 什么叫「空壳 / 无用报表」

满足**任一**即视为应删的空壳：

| 情形 | 说明 |
|------|------|
| 仅 `baseInfo` 建壳，**从未**成功 `saveReportDevInfo`（无 Field / 设计区空） | 临时名 `__build_*` / `__probe_*` / `__bench_*` |
| 布局保存失败 / 脚本异常退出 / 用户中止，留下未改目标名或不可用壳 | 列表里出现但点开空白或全 Const |
| 探测用临时报表（找表、压测） | 用完即删，禁止留在应用报表列表 |

**不要删**：已成功落库且已向用户交付设计器地址的正式报表（如「测试BBB报表-chl」「议题A」）。

### 1.2 何时必须删除

- 命令 / 脚本 **抛错退出**
- Agent **中止**当前建表任务（含用户叫停）
- 同一任务内 **重建**前：旧失败 `reportId` 先 `deleteReport`
- `finally` / 收尾逻辑：扫描本会话创建的临时壳并清理

```
POST/GET /api/bs/edc/report/deleteReport?id={reportId}
（或 multipart ids=；进回收站即可，见 report-lifecycle-api-guide.md §删除）
```

Header 须带 `ebBusinessId`=appId。可批量：`id=id1,id2`。

### 1.3 实现纪律

1. 建壳成功后立刻记下 `reportId`（变量 / 日志）；**禁止**只记名字。  
2. 成功改名并交付前，临时名壳仍算「进行中」；**失败路径必须 delete**。  
3. 向用户说明：「已删除失败产生的空报表 xxx」，避免列表残留。  
4. 禁止留下多个 `__build_*` 占列表。

## 二、单点失败不卡死（强制 · 失败前进）

### 2.1 步骤分级

| 级别 | 步骤例 | 失败策略 |
|------|--------|----------|
| **阻断** | 登录、找 app/表（预算内）、建壳、绑数据集、**布局 saveReportDevInfo** | 修 1 次或删壳重建 1 次；仍失败 → **提示用户**并停止交付假链接；清理空壳 |
| **可降级** | `saveQueryItem`、`saveQueryConfig`、数据集筛选、权限、快照；**用户点名的** verify/HTML | **最多重试 1 次** → **提示用户** → **结束**（禁无限轮） |

### 2.2 禁止卡死

- 同一 API / 同一报错 **连续尝试 > 2 次**（含重试）仍失败 → **必须停手**，向用户说明原因与需确认项。  
- **禁止**为 `saveQueryItem` 500 等可降级项循环试参、开浏览器抓包、阻塞不交布局链接。  
- **禁止**在「获取查询条件失败」上耗尽会话；布局已成功则**先交付设计器地址**。

### 2.3 对用户提示模板（可降级失败）

```markdown
⚠️ **查询条件未写入**（`saveQueryItem` 返回 …）
- 报表主体已保存，可先打开设计器查看布局。
- 请确认：是否仍需高级搜索条件「议题名称 / 申请人 / …」？
- 也可在设计器：页面 → 查询设置 → 手动添加。
- 我将在收尾再自动重试一次；若仍失败以你确认为准。
```

同类可替换：数据集筛选、权限、字段绑定抽检等。

### 2.4 推荐执行序（建表）

```
找表 → 建壳 → 布局落库 → 【立刻可交设计器地址】
  → 查询条件（失败则提示+跳过）
  → 其它可降级项（失败则提示+跳过）
  → 收尾：对失败的可降级项自动补救 1 次
  → 汇总：成功项 / 需用户确认项
  → finally：删除本任务产生的空壳
```

### 2.5 与交付合同

- 布局成功 → 遵守 `report-delivery-contract.md` §〇 **先交地址**。  
- 可降级失败 → **不阻塞**首轮链接；在回复中列出「未完成项 + 请用户确认」。  
- 阻断失败 → 不交假链接 + **删空壳** + 说明卡点。
