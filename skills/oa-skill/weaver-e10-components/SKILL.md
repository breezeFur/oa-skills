# E10 可配置组件

把需求实现为可注册、可拖拽、可配置、可保存的 E-Builder 自定义组件。用户只提出组件用途时，自行补齐实现、默认外观、空态和操作细节；重点保证人能通过设计器配置，配置真实生效且保存后保留。

## 工作入口

- 按 [CLI 自动准备](../cli-setup.md) 由 Agent 直接准备匹配版本的 `e10-cli`；缺少或版本不符时安装/更新 `weaver-e10-builder@1.5.4` 并验证启动，不把安装步骤退回给用户。

- 先读取相邻 `../weaver-e10-builder/SKILL.md`，复用它的认证、CLI、设计器及编译指导。登录态来自 e10-cli，技能和组件源码不保存凭据。
- 创建前查询当前环境的同名组件、唯一标识、分类和代码树。修改已有组件保留原 ID 与配置键；创建新组件使用当前环境可用的唯一标识。
- 根据组件用途读取 [配置设计](references/configuration.md)，形成配置清单，再实现配置面板和渲染代码。
- 组件调用 SQL 准备或出现“管理员正常、普通用户暂无权限”时，读取 [SQL 取数与权限](../weaver-e10-builder/references/coding/guide-prepared-sql-access.md)。运行页使用原生 SQL SDK/接口，不能使用管理端 getModelDatasetData；授权回读后仍须验证普通用户实际访问。
- 注册、编译、保存、导出时读取 [平台操作](references/platform.md)。[历史实例](references/examples.md)仅用于理解已验证的配置机制，不作为业务需求或跨环境 ID 来源。

## 核心交付要求

1. 每项开放配置写明：中文名称、配置键、输入方式、数据类型、默认值、允许范围、留空含义、作用位置、是否需要重新查询数据。配置清单与实际面板保持一致。
2. 常用配置提供普通人能操作的输入框、选择器或可增删列表；只有平台实际支持的控件才能使用。复杂 JSON 可作为高级入口，必须提供样例和中文校验提示。如果当前平台只验证了文本框，先交付可用文本入口，说明局限，不能声称已有可视化列表编辑器。
3. 配置闭环必须完整：面板字段 → 保存值 → 配置解析/归一化 → Design/View 消费 → 页面持久化回读。不要开放没有消费者的字段。
4. 不把应用 ID、页面 ID、数据集编号、字段编码、业务名称写成不可更换的常量。实例绑定由配置注入；平台运行上下文自动提供的值不要求用户重复填写。
5. 配置按实例隔离，同页放两个组件可以独立调整。共享筛选/数据状态使用明确的联动组，不使用固定页面 ID 或一个全局变量覆盖所有实例。
6. 设计态允许明确标识的预览数据；运行态展示真实数据以及加载、空数据、失败状态。失败不能伪装成零值，预览不能触发导出、写入或跳转。

## 实现与验收

按需求实现需要的组件文件，终端声明与实际实现一致。PC 的 Design/View 必须可用；只有提供并验证了 MDesign/MView 才交付移动端能力。不要从历史组件声明推定当前终端已验证。

配置解析统一处理字符串数值、布尔值、JSON 和默认值。保留未知的历史配置键，迁移已有键时提供兼容读法；`false`、`0` 与留空分别处理。变更绑定后重新加载数据，变更样式不应无谓查询；异步旧响应不能覆盖新配置的数据。

完成本地编译检查后，在用户指定环境保存组件源码及编译产物并回读。创建组件不自动授权替换所有页面实例、删除旧组件或执行导入迁移。页面实例的放置与保存按本次用户需求执行。

至少验证一个有代表性的实例：修改标题、尺寸或颜色、数据绑定及适用的交互配置，保存并重新打开，再在运行页确认效果；同页第二实例确认隔离。无现场验证条件时标明仅完成本地检查，不能称平台验收通过。

交付说明包含组件名称/唯一标识、设计器入口、用户可配置清单、关键配置示例和实际验证范围。用户要求导出时保留原生包，并区分“下载成功”和“目标环境导入验证成功”。
