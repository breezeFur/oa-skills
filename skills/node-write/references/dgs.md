# DGS 的类型盘点与读写验证

按当前文件的实际证据处理，不使用固定项目路径、固定后缀列表或“名为 Node 即已注入”的假设。加密行为可能同时取决于进程、目录、后缀、文件来源和策略；读取也可能触发 DGS 自身的物理状态转换。

## 盘点时区分三种证据

1. **策略声明**：从已授权、可读的策略或导出清单获得配置范围。专有加密容器只能报告不可读，不能把乱码猜成后缀或尝试解密；不输出包含密钥、凭证的配置。
2. **已有密文**：用已验证的独立观察器读取允许扫描目录中每个文件的少量二进制文件头，统计实际后缀。记录扫描根目录、排除项、错误及截断；跳过凭证目录、会话、缓存与未下载的云文件。密文被复制或改名后可能具有其他后缀，不能据此认定当前写入规则。
3. **新写入探针**：在目标目录分别用候选运行时写入同后缀的固定合成内容，核对明文读回及独立密文视角。记录观察时点；交叉读取可能改变物理状态，应在读取前后分别取样。

已有类型、探针阳性类型与全部策略类型不可混为一谈。盘点结果、实际路径、运行时指纹和证据留在本机，不放入开源技能。

## 准备独立观察器

可使用现成的只读观察器，也可在 Windows 本地编译本 skill 的 `scripts/file-header.cs.txt`。源文件用 `.txt` 保存，避免预先假定编译器可读取受控 `.cs`。先用 Node 确认源文件是有效明文；编译器参数使用绝对路径和 Windows 反斜杠。

```powershell
$nodeWriteObserverSource = 'C:\skills\node-write\scripts\file-header.cs.txt'
$nodeWriteObserverExe = 'C:\task\work\file-header.exe'
$nodeWriteCompiler = 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe'
& $nodeWriteCompiler /nologo /target:exe /reference:System.Web.Extensions.dll "/out:$nodeWriteObserverExe" $nodeWriteObserverSource
if ($LASTEXITCODE -ne 0) { throw '观察器编译失败' }
```

该程序只读一个绝对路径，输出 JSON：`bytes`、前 16 字节的 `headerHex` 和文件 `sha256`；不打印正文、不写目标文件。二进制存放任务 `work/`，不提交到技能仓库。跨平台可选其他实现，但其输出必须符合相同接口。

观察器的名称、编译方式或进程来源均不证明独立性。必须验证它对**同一个受控合成文件**看到预期密文，且 SHA-256 与 Node 明文不同；只看到不同文件或某个文件头不足以证明这一点。

密文前缀应来自本机已知有效受控文件或已确认策略。先用观察器检查，不打印正文：

```powershell
& $nodeWriteObserverExe 'D:\repo\src\known-controlled.ts'
```

`17DA5FA0` 是部分环境曾出现的标识，只能作复核线索；DGS 配置容器也可能使用完全不同的文件头，不据此推断业务文件策略。

## 同目录、同后缀探针

```powershell
& $nodeWriteRuntime $nodeWriteDgsScript probe --directory 'D:/repo/src' --extension '.ts' --observer $nodeWriteObserverExe --cipher-prefix '<本机确认的十六进制前缀>' --out 'C:/task/work/src-ts-evidence.txt'
```

脚本使用随机文件名和排他创建，写入固定 UTF-8 合成文本，逐字节核对 Node 读回，再调用观察器检查密文前缀及不同的物理 SHA-256。无论验证成功与否，仅删除本次成功创建的探针；不做递归删除或清理业务文件。`--out` 使用排他创建，不覆盖旧证据。

证据绑定实际 Node 与观察器的路径和二进制 SHA-256、验证时间、真实父目录、后缀与密文标识。换目录或后缀重新运行；`.d.ts` 单独验证。脚本无法探知远端策略是否已更改，策略变化、升级或新任务开始时按实际情况重新验证。该 JSON 是任务验证记录，不是安全签名或权限凭据。

如果观察器也读到明文，或该运行时在该后缀下写出了明文，探针失败；不能凭 Node 退出码、读回成功或其他目录的成功证据认定具备目标写入能力。

## 读取、输入与写后校验

- 先检查独立物理视角，再用已验证的 Node 读取工作区当前内容。`git show :<path>` 只代表暂存区，不能代替用户未提交内容。
- 对受控文本，读写命令同时提供 `--dgs-evidence` 和显式 `--observer`。脚本复核运行时、目录与后缀；原本为密文的目标读取后仍需符合已验证前缀，否则拒绝输出草稿并报告状态变化。
- 优先通过 Buffer/stdin 输入完整字节；需要草稿时才用 `.txt`。不要假定 Python、PowerShell、Node 生成或读取 `.txt` 的行为相同，也不要把暂存文件当作保密边界。
- 覆盖检查明文基线，新建用 `--create`。在原目标路径写盘，逐字节比较 Node 读回，然后复核独立密文前缀与不同的物理 SHA-256。验证失败时检查实际状态，不能宣称回滚。
- 原本为明文的已有目标不能借助新建探针推断覆盖后会加密，受控模式在写入前拒绝此类覆盖。普通文件可用普通模式；不要自行删除重建或改变策略来强制加密。空文件在部分策略下保持零字节，也无法通过密文头检查。
- 查看 Git diff 与待提交内容，确保仓库接收的是有效源码/文档；运行项目要求的必要检查。格式化工具、编译器和文档工具使用独立进程，也需检查它们的实际 DGS 能力。

严格 UTF-8 解码失败时区分：仍是密文、真实编码不同、正文已损坏。可通过文件头、格式和原编码证据判断；不要把每次乱码都归因于“Node 未注入”，也不要静默使用替换字符。二进制文件由对应格式工具处理。
