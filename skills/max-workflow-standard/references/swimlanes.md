# 泳道流程图的设计与保存

来源：2026-10-16 用户要求参考已有流程，将目标流程改成泳道，允许参考更多流程，并明确将此做法维护进本技能。属于[用户默认约定 UC-10](user-conventions.md)，不冒充 V2.1 公司 Word 原文新增条款。本文只保留可复用方法和已核实的工具限制，具体流程的人员、金额、ID、分组方案留在对应任务记录。

## 选择参考和设计泳道

1. 用户给出流程链接时，先读取该流程的实际图形和分组，并查看页面效果；必要时再对照同业务类型或审批结构相近的现有流程。参考前核实环境与对象，不能仅凭名字认定是合适模板，也不要求每次固定查询同一批流程。
2. 现有 MAX 典型通常将阶段作为列、职责作为行。阶段可包括申请、审核/决策、决策、执行；职责可包括申请部门内部审核、管理部门审核、实际执行岗位。按业务选择是否单列决策阶段、是否合并职责，行列数、名称和朝向不固定。
3. 将已确认的节点放入对应阶段和职责区域，采用清楚的顺序、对齐和留白。金额等条件分支要让处理路线可见，必要时显示出口条件；转折与标签避免遮挡节点和其他连线。总经理、财务、出库等职责只有在目标业务存在时才加入。
4. 泳道是流程图的表达方式。阶段、职责分组及节点坐标不代替实际连线条件、操作者或矩阵。复用参考布局时只借用组织方式与样式，目标节点、审批人、条件、权限仍来自本流程。
5. 既有图仅重排时，先保存图形和配置基线，列出保留的节点/连线身份、审批路线和本轮布局修改。普通字段、标题等局部调整不自动触发泳道重排；已有用户指定的其他图形方案照其要求执行。

## 保存前核对工具能力

平台查询与保存优先走现有 `oa-skill` 和配套 CLI。核对当前版本、帮助和实现；涉及泳道时不能只验证“支持保存 XML”。

2026-10-16 在配套 `weaver-e10-builder` / `e10-cli` 1.5.4 中实际核实：

- `workflow auto-layout` 主要做节点分层和坐标排布，不能据其成功认定已建立阶段/职责泳道。
- `workflow save-layout` 的保存报文将 `groups` 固定为 `{"col":[],"row":[]}`。此实现不能直接用于需要保留或新增泳道的保存；否则可能清空分组。升级后重新查当前实现，不把该限制永久套用到其他版本。
- `chart/getXml` 返回的 `data.groupDetail` 与图形 `data.xml` 是两份相关信息。泳道需要同时保留/更新 `groups.col`、`groups.row`；仅在 XML 改节点坐标不够。
- `getXml` 中 `node_…`、`link_…` 是服务器格式。该版本 `chart/saveLayout` 需要浏览器格式的纯数字 cell ID，以及对应数字 `source/target` 引用。使用已核实的工具包转换，保持真正的 `nodeId/linkId`；原有元素不能标为新增。

若高层命令未完整支持分组，按[操作与验收](implementation.md#改名和工具能力不足时)先核实工具包及当前设计器的实际请求，再复用工具包认证和客户端提交已核实报文。不要自行拼猜测接口，也不把本次带固定资源ID的一次性脚本复制进通用技能。

## 已核实的接口要点

以下为该版本的实现线索，用于检查真实报文；不是允许脱离现有工具和当前源码直接照发的固定模板。

| 项目 | 读取或保存要点 |
| --- | --- |
| 图形与分组 | `/api/bs/workflow/pathdef/chart/getXml` 返回节点、边、模板、出口显示选项与 `groupDetail`；先记录当前值 |
| 分组身份 | 当前设计器使用 `chart/generatorId`；新增分组可带 `isAdd`，已有分组沿用正式ID。服务端保存时可能重新分配新分组的正式ID，以回读结果记录，不误判为失败或反复重建 |
| 分组内容 | `type` 为 col/row，保留 `value`、`panelWidth`、`position` 及已有多语言属性；坐标和尺寸按当前实现判断，不能把 header 偏移或累计边界当所有版本通用常量 |
| 保存 | `chart/saveLayout` 同时接收图形、`groups`、`deleteGroups`、模板与出口条件/名称显示选项。仅修改本轮授权部分；保留已有分组和未涉及的显示设置，勿复制参考流程的正式分组ID |
| 并发与签出 | 遵循当前设计器的签出/锁定机制；写入前与基线比较，发现他人已改则重新读取并合并。只操作目标流程，不为验证保存而改参考流程 |
| 编码 | 该实现图形采用 UTF-8 XML、Base64，再对表单传输的特殊字符作工具规定处理；分组中的 HTML/特殊字符也需按已核实的请求方式处理 |

保留准确的字符串资源ID，避免大整数经过数字转换失真。泳道图中无需新增审批节点就能清楚表达的结构，不为排版额外创建节点、角色或审批条件。

## 保存后验收

- 确认接口业务保存成功及校验结果；记录提示。提示“未设置默认出口”时核对是否原有状态、现有条件是否覆盖业务范围，不为消除提示擅自添加无条件业务路线。真正校验失败须停止依赖保存结果的后续操作，重新读实际状态后处理。
- 回读正式泳道的数量、名称、ID、尺寸和边界，以及所有目标节点坐标。新分组生成正式ID是正常身份变化，仍须核实没有丢失或重复分组。
- 既有图重排时，按 `nodeId/linkId` 比较节点类型、连线方向、出口条件和操作者；按字段ID比较节点显示/只读/必填权限。同时核对本轮写接口可能影响的标题、编号、字段公式/联动、附件及打印绑定。
- 对无业务顺序的权限返回列表，可先按字段ID对齐；只排除已确认的耗时、签出提示等元数据。节点顺序、出口优先级、分组顺序和公式参数等有业务意义的次序不能任意排序后忽略差异。
- 在浏览器查看保存后的完整流程图：阶段和职责标签清楚，节点归属正确，起止及分支可见，连线和条件文字无明显遮挡。可用页面缩放检查全图并保存截图，不能以接口成功替代页面验收。
- 分别报告配置回读、图形页面和实际审批流转的验证范围。布局验收不自动授权发起或推进审批实例；已有相应授权则按其边界执行。

交付时提供目标泳道图的实际链接、参考依据、本轮变更范围和截图，详细校验使用[核对记录模板](../assets/templates/review.md)。
