## 字段及解释

节点全表 9 列：流程名称、流程版本、流程 ID、流程组名称、流程组 ID、节点名称、节点 ID、所属阶段、标准时效。

**流程级时效的单位明确为小时；节点级字段表头只写“标准时效”，没有明示单位。** 查询脚本对节点单位返回 unknown，实际配置前从业务/当前平台补核，不能只因数值相似就断言单位或当成天。流程总时效不直接分摊给节点。

## 查询和应用

```text
python scripts/search_timeouts.py --name "成本数据申请" --kind workflow
python scripts/search_timeouts.py --name "IT信息类合同评审流程" --kind node --node "部门经理"
python scripts/search_timeouts.py --name "客情" --kind all --contains --limit 20
```

默认精确匹配流程名；查询结果的 source_row 指原工作表行号；可加 `--version` 和 `--node` 精确匹配。`--contains` 仅用于发现候选，输出标 `candidate_only`，必须回到精确对象后再采用。默认最多显示 20 行，同时报告实际匹配总数与是否截断；重复记录全部保留，不静默选第一条。默认无精确匹配时不会自动搜索相似名。

读取结果后核对同名不同版本、组织/分组、节点名、阶段和源 ID。历史源 ID 不是当前 E10 ID，不可直接写入当前流程。原件没有精确匹配“客情申请/客情物资申请/IFS102”的记录，不能用“礼品申报”或“业务招待费”的时效替代。

实际时限设置还需业务确认计算口径：自然时/工作时、节假日、起算时刻、超时动作、通知对象及重复提醒。文档没给出这些通用值，缺项应显式记录。
