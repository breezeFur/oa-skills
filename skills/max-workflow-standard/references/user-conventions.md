# 用户确认的 MAX OA 默认约定

2026-10-15，用户在流程任务复盘后确认以下默认做法，适用于创鑫 OA/E10 工作流程及配套表单。这些是协作和实施约定，不是公司 Word 原文。具体流程的名称、字段数量、金额条件、人员映射等不收录于此。

## 适用边界

- 用户本轮明确要求及已经确认的业务决定优先；默认约定只补充未指定的实施选择。公司明确要求与本轮需求冲突时，说明差异及影响，已有明确例外则在其范围内执行，不反复询问。
- 单个流程的暂缓、特例和现场修正保留在该任务的计划或核对记录，不自动改成全公司的标准。
- 本页与 [公司规范](standards.md) 分开维护；平台操作步骤见 [操作与验收](implementation.md)，不修改供应商工具 skill 来保存公司偏好。

## 默认做法

| 编号 | 默认做法 | 边界 |
| --- | --- | --- |
| UC-01 | 新建或改造表单时，先找同类典型表单，默认复用公司真实 Logo、表头、字体、分区、列宽和输入区样式，再按目标业务修改 | 用户明确另做样式时按其要求；仅复制样式，不照搬源审批人、权限、业务条件或 Owner |
| UC-02 | 所有 OA 查询和增删改优先使用 `oa-skill` 及其配套 CLI | 缺少命令时查匹配版本的帮助、文档和实现，再使用已验证接口及现有认证；浏览器用于必要查证与页面验收 |
| UC-03 | 工作流管理中的审批需求默认使用原生团队工作流程；独立维护的主数据使用 E-Builder 表单；创建前查询并复用适合的已有对象 | 用户明确要求个人测试流程或其他资源类型时按其要求；流程定义、业务表单、动作流不可混作同一对象 |
| UC-04 | 审批操作者先查现有矩阵，再查角色，核对组织、行条件、列含义和有效成员 | 不凭节点名字猜具体人员；实际矩阵、角色或指定人按本流程已确认业务选择 |
| UC-05 | 只搭建需求明确需要的字段、明细和功能；样表足够清楚时直接沿用 | 不预加“以后可能有用”的字段；公司必需系统字段和实际计算、联动依赖仍须保留；精简不等于删除存量数据 |
| UC-06 | 标题、编号、组织信息带出等先查平台原生能力与本流程现有配置 | 不另造同名业务字段或重复功能；修改前说明实际配置位置、作用对象和影响范围 |
| UC-07 | 改名时检查流程定义、表单表头、打印模板、菜单、台账及附件目录等关联位置 | 按各对象用途确定名称，不强制全部同名；优先保留资源 ID、数据和引用；共享资源先确认是否应随本流程改动 |
| UC-08 | 审阅发现现状与旧记录不同，先查最新用户决定和现场配置，再判断是否为缺陷 | 用户已确认的业务变更更新本任务依据，不擅自恢复旧值；原因未知时列为待核实差异 |
| UC-09 | 文档与现场典型做法有差异时，先查询真实参考流程，再报告差异、影响及建议 | 既有流程是参考证据，不能自动覆盖公司规范；用户认可的例外只适用于认可的范围 |
| UC-10 | 新建流程图或用户明确要求重排流程图时，默认参考同类现有流程采用泳道，按业务阶段与处理职责组织节点；有指定参考先读指定流程，必要时再比较其他典型流程 | 2026-10-16 用户确认纳入默认做法。泳道数量、名称和方向按目标业务确定，不固定套用某个案例；仅改字段、标题等局部任务不顺带重排既有图。操作与验收见[泳道指南](swimlanes.md) |

## 仍需业务决定的事项

先查需求、已有确认和现场配置；仍无法唯一确定且影响实施时，再向用户提出具体问题及候选依据，不把下面的项目逐次机械重问：

- 图、节点表和文字互相矛盾，尚无明确的适用版本或优先来源。
- 同名节点可能对应不同组织范围、矩阵行列或角色，且实际职责仍不清楚。
- 主数据维护人、查看范围、代填权限等尚未定义。手工维护不等于所有人可编辑；申请人是否锁定也不是统一默认值。
- 标题或联动要求引用了未定义的业务字段。先核实是否已有来源，不自动扩建表单。
- 编号重置、金额临界值、精度、退回或分支语义仍有多种解释，并会改变业务结果。
- 真实审批实例测试所需的账号、数据或提交范围尚未获授权。已有相应测试授权则沿用，不增加重复批准步骤。

## 验收与交付

配置保存回读、页面与打印、真实数据联动、审批实例流转分层报告；未做的层级明确保留。提供本流程实际管理位置、可点击入口、完成范围及剩余问题。验收方法以 [操作与验收](implementation.md#完成状态及证据) 为准。
