# OA 操作、需求落地与验收

本页记录 MAX OA 操作方法和已验证的实施经验，不声明某个具体流程的当前状态。公司 Word 原文要求见 [公司规范](standards.md)，用户确认的通用默认做法见 [用户默认约定](user-conventions.md)。

## 选择对象和工具

1. 按 UC-02 使用当前环境可用的 OA 工具 skill 及配套 CLI。操作前核对技能要求、CLI 版本与当前 `--help`，不把一次实施使用的版本永久固定。
2. 找到安装根目录中的 `oa-skill/weaver-e10-builder/SKILL.md`。它指导命令与平台限制；本技能给出 MAX 业务规范。不要把整个供应商技能复制进本技能，也不要假设其总在某个用户的绝对路径。
3. 远端操作前在实际 CLI 连续阶段确认 auth profile、base URL 和权限。纯规范整理和本地文件工作不登录 OA。认证材料只由工具维护，不写入本技能、计划或日志。
4. 没有现成子命令时先查匹配版本文档、`--help` 和工具包实现。确需复用客户端时使用已验证的 OA 接口及现有认证；不能猜 URL、报文或硬编码凭据。
5. 浏览器用来核实页面、接口或验收视觉；不因命令暂时没找到就退回成全程手工点 UI。配置回读已足以验证的机械项不重复逐页检查。

用户没有要求本任务查询 OA 时，不为了“确认 skill 有效”而登录、创建、发布或提交实例。

## 原生工作流程与 E-Builder 主数据

| 对象 | 本项目用途 | 正确资源边界 |
| --- | --- | --- |
| 原生团队工作流程 | 工作流管理中可查、由组织发起的审批流程 | `workflow create-workflow` 及 `wf-form`；记录 workflowId、formId、机构与分类 |
| 原生个人测试流程 | 用户明确需要的个人测试 | 不能用其创建成功证明团队列表可见 |
| E-Builder 应用表单 | 独立维护业务主数据、台账和关联选择数据源 | `form` 资源，记录 appId、objId、viewId、菜单及权限 |

上述为此次配套工具的命令族示意，具体参数以当前 `--help` 为准。已有对象的资源 ID 类型与接口前缀不可混用。业务要求团队流程时检查 belongType/机构归属和团队列表入口；只有流程定义存在不等于已交付可发起菜单。

## 读需求、处理冲突和执行计划

- 同时读取 Word 正文、表格、图示、批注、嵌入对象；Excel 需要工作表、合并布局、节点表和图形。文件名版本、文内日期、修订批注日期分别记录，不从“1016”推出 2026-10-16。
- 后续用户明确纠正覆盖旧计划。需求图、节点表和文字有冲突时，保留冲突来源；用户已指定依据后同步本任务计划，不再重复用已作废材料否定确认结果。
- 把通用规范、当前业务规则、示例、工具限制、推断与未决项分开。金额门槛、矩阵列、字段数量不能从别的流程套来。
- 建表前确定 FLOW/EXCEL 类型；样表已清楚给出表格式或用户已确认时沿用，不反复提问。不可切换的布局选择仍不明确时，继续独立的只读梳理并提出该项问题。
- 实际多资源搭建按当前 OA Builder 的 `references/common/guide-plan-template.md` 写具体 `plan.md`，包括逐行布局蓝图、字段、关联、公式、权限、编号、节点、出口、设置、菜单、打印、报表与验收。核对后才逐项打勾并回填实际 ID。
- 遵守已存在的授权，用户说“开始干吧”“继续完成”后继续相应范围。需要业务决定的事项先按用户默认约定检查已有依据，只有仍影响实施时才提问；不把超时当作答案或同意。
- 本技能不增加额外的统一审批关卡。若实际工具技能或项目规则明确要求确认，应先完成可审阅的计划，再引用具体文件及原句说明原因；不要把文档中双方签字要求扩成每次小改都必须重新签字。

## 审批人来自真实矩阵或角色

用户说明：大部分审批在矩阵中，少部分选角色。先查询现有审批矩阵、部门矩阵、分部矩阵和业务需要的角色，确认组织范围、字段映射、行选择条件、列含义及有效成员。不要看到“行政总监”就写死某个人，也不要假设岗位标签一定是系统角色名称。

查清同名矩阵、公司、部门和列是否真实对应；没有对应列时记录依赖，不创建一个名字相同的假角色。当前申请人部门、公司与固定总部范围是不同选择，按已确认业务决定。具体映射只记录在本任务计划和证据中。

## 复用典型表单样式

按 UC-01 默认参考同类典型表单，尤其复用真实 Logo 再修改，无须等待用户逐次提醒。

1. 查询候选典型表单并读取当前布局，确认它的表单体系、布局类型及是否确实属于同种 MAX 风格。
2. 记录来源、目标以及实际改动。优先复用 Logo 资源引用、表头单元格、标题、Owner、红色斜角区块、列宽、间距、字体、灰色标签、浅蓝输入区。
3. 将源字段引用映射到目标；保留目标字段 ID、公式、联动、必填、只读、隐藏字段、节点权限和业务数据。
4. 复制样式不能连同源流程的审批人、金额条件、数据源、权限或旧 Owner 一起照搬。已有表不全表初始化、不因为调整几个位置重建整个布局。
5. 默认 PC 表单变化后更新本流程打印模板，核对适用节点。浏览器按需查看实际新建/查看效果及打印预览；未查看就保留“未视觉核验”。

包内图片是规范证据，不是可直接导入的完整平台模板。实际平台布局和 Logo 引用需通过当前工具获取。不要从整张截图截出模糊 Logo 充作原版资源。

## 流程图与泳道

流程图新建及重排按 UC-10 采用泳道时，读取[泳道设计与保存](swimlanes.md)。先查询实际参考图的分组、节点位置和分支走线，再组织目标业务；保存时同时处理泳道分组和图形，回读核对原审批配置，并在浏览器检查完整效果。

## 标题、编号、字段与主数据联动

- 系统标题、编号的配置与普通业务字段不同。标题是否在新建时生成、保存/提交后是否重算，应分别查开关和规则。
- 标题变量清单不等于实际标题模板。读取本流程的开关、模板及变量映射；若写接口保存整组功能设置，先回读并保留同组其他开关，保存后逐项核对，避免只改模板却重置生成时机。
- 特殊标题包含流程编号时，编号未生成前只能显示已可用部分；保存/提交后的完整规则需独立回读，并在获授权的实例中验证。不要为了验收随便发起审批。
- 日期按已确认的创建/申请日期来源；若业务要求创建日期，不能在隔天提交时静默换成提交当天。
- 标题引用项目名称而表里没有项目字段时，列出缺口；不凭空增加“项目名称”字段，也不假装已实现这段。
- 编号格式、流水位数、是否按日重置是不同问题。只确认了格式不能宣称已确认每日重置。
- 主数据关联要核对目标真实对象、选择窗口显示列、过滤条件、单位/单价带出、数量与金额计算、字段权限。界面里隐藏单价可以供计算，不能因不显示就删除计算依赖。
- “相关流程”若要求关联具体申请单，选择对象应是流程实例；流程定义或路径浏览器不能代替申请单。查同类参考字段的实际组件、目标类型与返回值，保留目标字段 ID，并在选择窗口核实能选到具体单据。
- 数量、单价与金额联动可能异步更新。等待本次联动完成、值稳定后再判断计算结果；短暂的旧值或零值不足以判定公式失败。验收计算值和字段实际可编辑性，区分布局属性与节点权限的最终效果。
- 用户要求精简字段时保留既有数据及被引用的资源 ID；若有业务数据，先调整布局、台账和选择窗口，慎重处理物理字段。不能把“减少可见列”说成“数据库已删除列”。

## 改名和工具能力不足时

改名前按 UC-07 列出本流程拥有的资源与共享资源，读取实际 ID、名称和引用。分别更新需要改名的位置；附件目录改名后回读普通附件、签字意见附件的目录 ID、路径与名称，确认引用仍有效。不为了改名移动文件、重建表单或更换资源 ID。

CLI 缺少改名、布局样式复制、原生字段类型或节点权限等命令时，先核实当前版本是否支持；现有技能没有说明的能力不宣称已具备。需要接口操作时先读目标、确认报文语义，保存后回读，并记录本次实际工具和验证范围。只有多次重复且输入输出稳定的操作才提炼为参数化脚本；不把带固定资源 ID、人员或本地路径的一次性脚本直接写入通用技能。

本地 Word/Excel 普通读取失败时，先区分文件占用、格式损坏和受控文件，不能直接归因。可用匹配版本 CLI、只读 OOXML 或已经验证的本地 Office/WPS 只读接口交叉核实；读取方式应与文件类型匹配，未验证原因前不反复要求用户打开、关闭文件。

## 完成状态及证据

用 [核对记录模板](../assets/templates/review.md) 记录每项规则：符合、部分符合、不符合、未验证、不适用、用户明确暂缓。每项状态须有对象和来源；不适用与暂缓写理由。

| 证据层级 | 可以声称什么 | 不能据此声称什么 |
| --- | --- | --- |
| 文档和需求核对 | 要求已识别，冲突已记录 | OA 已配置 |
| CLI/API 保存后回读 | 配置保存且目标值一致 | 页面效果、真实人员命中、实例流转成功 |
| 页面与打印核验 | 本次页面/打印显示正确 | 所有节点权限、关联数据及审批路线都正常 |
| 真实数据交互 | 选择物资、带出值、金额重算等本次交互通过 | 提交、审批、退回、归档已通过 |
| 授权审批实例测试 | 指定账号、数据、分支及节点的实际流转通过 | 其他组织/分支/移动端未经测试也通过 |

验收至少覆盖本轮变化涉及的规范；金额分支测临界值，人员矩阵测组织匹配，权限检查发起/审核/归档相关阶段。额外验证应解决实际疑点，不反复重复已通过的机械检查。

交付说明提供实际后台位置、菜单路径、可点击的正确环境链接、资源身份、完成项及未决项。发起链接、管理链接、设计器链接分别提供；不能把带登录重定向的页面当作已成功进入流程。
