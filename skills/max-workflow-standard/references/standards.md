# 逐条规范及适用条件

本页提炼公司要求，保留正文和截图的差异。`Pxxx` 是原始 Word 顶层正文段落编号；`T1/T2` 是原表；`图n` 按文档出现顺序编号，见 [截图解读](screenshots.md)。这些是包内定位符，不是页码。

来源标识：**正文**为明文要求，**截图明确**为红框、红字及直接展示的样式，**按需**为原文保留业务选择的项目。用户确认的通用补充单列在 [用户默认约定](user-conventions.md)，操作方法见 [操作说明](implementation.md)，不冒充 Word 原文；具体业务例外只记录在对应任务。

## 节点、出口与审批路线

| 编号 | 要求 | 来源与验收方法 |
| --- | --- | --- |
| MAX-10 | 发起节点名 `XXX发起`；中间节点名 `XXX审核`；存在直接结束出口的中间节点名 `XXX审批`；结束节点名 `归档` | 正文 P022；图6。这里的“审核/审批”是名称后缀，不能由后缀擅自改变平台节点类型 |
| MAX-11 | 节点列表先发起，再审核组，再审批组，最后归档 | 正文 P026；图7。原文“第一/第二/第三/最后顺序”指分组次序；不保证平台 sort 字段必须写成相同数字，也不表示审核节点并行 |
| MAX-12 | 实际流转依据经确认的节点表、连线及分支 | 实施解释：列表顺序不能代替连线；例图中节点与人员只展示规范，不是其他业务的默认路径 |
| MAX-13 | 出口名与目标节点一致，使用自动填充；修改目标后重新填充 | 正文 P028-P029；图8。同步查目标 ID 与出口名，保留原出口条件 |
| MAX-14 | 同源出口按业务条件大小排序；条件出口优先于无条件出口；通往归档的出口置于列表最后 | 正文 P032；图9红字。多个条件分支内部的具体排序仍按实际业务。归档最后不代表取消条件优先；两者冲突时结合源节点及实际匹配规则处理 |

不要把同源无条件出口当作安全默认而覆盖条件分支。对金额、人数、日期等边界分别核对等于、小于、大于、空值及计算失败；条件必须覆盖本轮业务定义的范围。

## 平台映射时必须保留的区别

- **“号”与渲染单位**：原图写 24/18/16 号，没写 CSS px 或 Word pt。优先保留原典型表单的实际样式值和单位；改版时同时记录规范值、平台数值、渲染效果，不能凭空乘除换算。
- **系统标题与页眉标题**：流程实例标题、流程定义名、单据页眉、流程编号是不同对象。改名需检查相关页面与打印，不把它们合成一个字符串写到所有地方。
- **节点列表与路线**：图7规范的是列表次序；业务的串行、并行、金额分支由已确认需求决定。
- **历史名称调整与数据迁移**：MAX-09 不等于允许改数据库列名、重新编号或重写历史单据。
- **模板可复用部分**：样式和真实 Logo 可复用，人员、字段 ID、接口绑定、权限、金额分支、时限、数据源 ID 必须映射到目标对象。
- **正文与截图冲突**：原件完整保留。按用户最新明确要求解决；尚未解决的冲突列成具体问题，不静默任选一个。
