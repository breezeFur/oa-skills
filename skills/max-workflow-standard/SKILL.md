# MAX 创鑫工作流程搭建规范

把公司规范落实为可核对的流程配置、表单和交付证据。规则基线为用户提供的 V2.1(1016) 文档，2026-10-15 完成原件与历史聊天复核；这不是对所有现有 OA 流程合规性的声明。

## 先读什么

- 所有 MAX 流程及配套表单任务：读 [逐条规范](references/standards.md) 和 [用户默认约定](references/user-conventions.md)。规范原文、用户约定与本轮业务要求分别识别。
- 查询配置、制定实施计划、搭建、修改或验收：再读 [操作与验收](references/implementation.md)。纯规范问答不必加载无关操作细节。
- 新建流程图、泳道设计、参考已有流程重排图形：读 [泳道设计与保存](references/swimlanes.md)，按 UC-10 参考同类流程的阶段和职责划分。
- 分类、L1/L2、编码或目录：补读 [完整分类表](references/classification.md)。
- Logo、表头、布局、字号、截图中的开关：读 [28 张图片逐图解读](references/screenshots.md)，打开涉及的原图。
- 审批时限：读 [历史时限数据说明](references/timeouts.md)，按需运行 `scripts/search_timeouts.py`，不要把整张时限表加载进上下文。
- 需要逐字复核：查 [CLI 转录原文](references/source-original.md)、[原文定位与结构](references/source-inventory.json) 或 [保留原件](assets/source/创鑫项目建设工作流程搭建规范V2.1%281016%29.docx)。[资料来源](references/provenance.md) 解释版本、图片编号和证据边界。

## 使用方式

1. 识别任务是规范问答、只读审阅、实施计划、实际搭建还是验收。遵守用户已经给出的编辑授权、暂缓项及纠正；“看规范”本身不授权改 OA。默认约定填补未指定的做法，不替代公司明确要求；已确认的业务例外只适用于对应范围。
2. 确认业务对象及资源归属。MAX 工作流管理中的团队流程使用原生工作流程；独立业务主数据用 E-Builder 表单。已有对象先查后复用，避免重复创建。
3. 把本轮需求逐项映射到规范编号；记录规则、业务值、来源、实际资源、状态与证据。可用 [核对记录模板](assets/templates/review.md)；实际搭建的 `plan.md` 仍按 OA Builder 的模板。
4. 查询与增删改优先使用可用的 `oa-skill` 及其配套 CLI。此技能负责 MAX 规范；工具参数与能力边界查匹配版本的 OA 工具技能，不猜命令或接口。
5. 完成授权范围内的工作后，分别报告配置回读、页面效果、真实数据联动、实例流转的验证结果。待确认、暂缓和工具不支持的项目明确保留。

## 每次都要守住的要求

- 系统流程标题、系统流程编号直接复用；申请单位的数据库名必须是 `sqdw`。
- 基本信息顺序：流程标题、流程编号、申请人、岗位、工号、申请单位、申请部门、申请日期。
- 节点命名与节点类型分开判断；列表排序与实际审批路线分开判断。出口改了目标后重新同步名称。
- 新建或明确重排流程图时默认采用同类流程的泳道表达；分组和坐标调整须核对原节点、操作者、条件与权限，见 UC-10 及泳道指南。
- 中间审核节点开启异常处理，选择“由用户指定操作者”；七类操作的意见必填。
- 附件及签字意见附件使用同一个 `流程附件/L1/L2/流程名称` 目录。
- MAX 公司表头和真实 Logo 优先复用现有典型表单；标题 24 号、分区 18 号、字段 16 号，具体平台数值和单位以模板回读为准。
- 打印模板跟随默认表单；提交后显示并停留在流程图的设置覆盖 PC、移动端。
- 自动处理、时限、权限、撤回主体、业务分支及编号重置规则按业务确定；不从截图中推定未说明的全局要求。
- 无法核实的项目不标完成；已获授权的独立工作继续推进，不因一个缺项阻断整个任务。
